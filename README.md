# Яндекс Диск для Linux (ydx)

> **English TL;DR:** Unofficial Yandex.Disk desktop client for Linux (Python +
> PySide6/Qt 6): full file browser, photo gallery with built-in viewers, public
> links, trash, transfer queue, tray icon and optional control of the official
> `yandex-disk` daemon. Log in with your own Yandex OAuth key — no credentials
> are bundled in this repo. Russian documentation below.

Неофициальный настольный клиент Яндекс.Диска в духе Windows-приложения:
полноценный файловый браузер, фотогалерея со встроенными просмотрщиками,
публичные ссылки, корзина, очередь передач и управление официальным демоном
`yandex-disk`.

**Неофициальный клиент. Не связан с Яндексом.**
«Яндекс» и «Яндекс.Диск» — товарные знаки ООО «Яндекс».

## Возможности

**Файлы**
- Список и сетка, превью изображений, хлебные крошки, поиск в текущей папке
- Все операции: создание папок, переименование, копирование, перемещение,
  удаление в корзину и восстановление
- Загрузка drag&drop и через диалог, скачивание с выбором папки
- Значки состояния: доступно офлайн / синхронизировано / только в облаке

**Передачи**
- Очередь загрузок/скачиваний с прогрессом, паузой, отменой и повтором
- Разрешение конфликтов при перезаписи, лимит размера файла (1 ГБ без
  подписки, 50 ГБ с Яндекс 360 — по данным API)

**Фото**
- Галерея по датам + «Альбомы» (группировка по папкам)
- Встроенные просмотрщики фото и видео (Qt Multimedia/FFmpeg) — файл
- скачивается во временный кэш и открывается без внешних приложений

**Ссылки и корзина**
- Публичные ссылки (publish/unpublish) с копированием в буфер
- Раздел «Общие», «Недавние», корзина с восстановлением

**Синхронизация (опционально, через официальный демон `yandex-disk`)**
- Старт/стоп/пауза на 2 часа, выбор папки синхронизации, exclude-dirs,
  режим read-only
- Баннер прогресса синхронизации (процент и скорость) с кнопкой
  «Синхронизировать сейчас»
- Автоперезаливка локально изменённых скачанных файлов
- Детект paywall-ограничений демона (требуется подписка Яндекс 360 —
  приложение сообщит и продолжит работать через REST)

**Интерфейс**
- Трей: клик открывает окно, «✕» и Ctrl+W сворачивают в трей
- Светлая/тёмная/системная тема, языки RU/EN (переключение без перезапуска)
- Автозапуск (опционально), до 2 аккаунтов, центр ошибок

## Установка

Linux Mint 22 / Ubuntu 24.04 (и близкие). Ничего не ставится в систему —
venv и зависимости живут в каталоге проекта.

```bash
./install.sh        # проверит системные пакеты и создаст venv
./run.sh            # запуск
```

Если системных пакетов не хватает, `install.sh` напечатает готовую команду
`sudo apt install …` — выполните и запустите снова.

Ярлык в меню приложений:

```bash
cp yandex-disk-linux.desktop ~/.local/share/applications/
```

## Первый вход: свой OAuth-ключ (~5 минут, один раз)

Приложение работает с Яндекс.Диском через публичный REST API, поэтому для
входа нужен **свой** OAuth-ключ (в этом репозитории никаких ключей нет):

1. Откройте **https://oauth.yandex.ru/client/new/** и войдите в аккаунт.
2. Название — любое (например, «Мой диск-клиент»).
3. Платформа: **«Веб-сервисы»**. В поле Redirect URI вставьте:
   ```
   http://localhost:8917
   ```
   (нужно только для входа «через браузер»; для входа по коду устройства
   redirect не требуется, но поле лучше заполнить)
4. Доступы: **Яндекс Диск REST API** → отметьте
   - `cloud_api:disk.read`
   - `cloud_api:disk.write`
   - `cloud_api:disk.info`
   - `cloud_api:disk.app_folder`
5. **Рекомендуется** также включить доступ **Яндекс ID → «Логин, имя и
   аватар» (`login:info`)** — тогда приложение покажет ваш настоящий логин,
   имя и аватар в сайдбаре (без него — обезличенный «Аккаунт»). Если
   включаете позже — просто войдите заново.
6. Нажмите «Создать приложение» и скопируйте **ClientID** и **ClientSecret**
   со страницы приложения.
7. При первом запуске клиента вставьте их на странице входа.

Способы входа:
- **По коду устройства** (проще всего): приложение покажет код — откройте
  `https://oauth.yandex.ru/device`, введите код и подтвердите.
- **Через браузер**: откроется Яндекс ID, ответ вернётся на `localhost:8917`.

Токены хранятся в GNOME Keyring (libsecret); если он недоступен — в файле
`~/.config/yandex-disk-linux/tokens.json` с правами 0600 (приложение предупредит).
ClientID/Secret — в `settings.ini` с правами 0600.

## Синхронизация с официальным демоном

Раздел «Синхронизация» работает через официальный демон `yandex-disk`
(`sudo apt install yandex-disk` или с сайта Яндекса). Приложение само
пишет его конфиг и passwd-файл (0600), запускает и останавливает его.
Без демона всё остальное (файлы, ссылки, корзина, фото, передачи)
работает через REST API.

## Каталоги данных

| Что | Где |
|---|---|
| Настройки и OAuth-ключ | `~/.config/yandex-disk-linux/settings.ini` (0600) |
| Токены | GNOME Keyring или `~/.config/yandex-disk-linux/tokens.json` (0600) |
| Конфиг демона | `~/.config/yandex-disk-linux/daemon.cfg` + `passwd` (0600) |
| Кэш (превью, временные файлы, лог) | `~/.cache/yandex-disk-linux/` |

Лог приложения: `~/.cache/yandex-disk-linux/app.log` (ротация 1 МБ × 3) —
его просят приложить к bug-репортам.

## Разработка

```bash
./install.sh                                                    # один раз
QT_QPA_PLATFORM=offscreen ./venv/bin/python3 -m pytest tests/ -q # тесты (48)
./run.sh                                                        # запустить
```

Структура:

- `ydx/core` — REST API и OAuth, без Qt (тестируется напрямую)
- `ydx/services` — настройки, аккаунты/токены, демон, превью, i18n
- `ydx/ui` — окна, страницы, модели, тема
- `vendor/lib` — запасная `libxcb-cursor.so` для Qt ≥ 6.5 (ставится и через
  apt; используется, если системной нет)

Ключевые механизмы:
- OAuth refresh под локом; при ротации refresh-токена хранится короткая
  история прошлых токенов как fallback (краш в окне ротации не разлогинивает)
- Токены — GNOME Keyring, файловый fallback 0600
- Single-instance: второй запуск поднимает уже открытое окно

## Безопасность

В коде нет ни ключей, ни токенов: ClientID/Secret вводятся при первом входе
и хранятся в `~/.config/yandex-disk-linux/settings.ini` (0600), токены —
в GNOME Keyring или `tokens.json` (0600). Всё это вне репозитория и
дополнительно перечислено в `.gitignore`.

От случайной утечки страхуют хуки в `.githooks/` (блокируют коммит и пуш
значений, похожих на ClientID/Secret или OAuth-токен, и файлов с секретами).
В этом клоне они уже включены; в свежем клоне включите один раз:

```bash
git config core.hooksPath .githooks
```

Осознанный обход (если хук сработал на не-секрет): `git commit --no-verify`.

## Известные ограничения

- С июня 2026 двусторонняя синхронизация через официальный демон требует
  подписку Яндекс 360; REST-функции (файлы, ссылки, корзина, фото) работают
  на бесплатных аккаунтах.
- Лимит загрузки через API: 1 ГБ на файл без подписки.
- Поиск — в пределах открытой папки (не по всему диску); нет resume докачки
  с байта, ZIP-скачивания папок, скриншотов/заметок из Windows-клиента.
